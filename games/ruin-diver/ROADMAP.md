## 1. 현재 게임 방향

**동굴에 갇혔다. 배고픔·목마름·빛을 관리하며 300m 아래 출구까지 살아서
내려가라.**

Ruin Diver는 자원 관리 생존과 동굴 탐험을 결합한 2D 픽셀아트 게임이다.
한 번의 탐험에서 자원을 채집하고 유물과 코인을 획득하며, 탐험 결과를
바탕으로 장비와 거점을 발전시킨다.

핵심 반복 구조:

``` text
동굴 탐험
  → 자원 채집 및 생존
  → 랜덤 이벤트와 비밀 장소 발견
  → 유물·희귀 자원·코인 획득
  → 탈출 또는 탐험 종료
  → 도감·기록 갱신 및 거점 발전
  → 장비 업그레이드
  → 더 깊은 동굴 탐험
```

## 2. 추가하기로 한 핵심 시스템

아래 5개 시스템을 향후 개발 범위에 포함한다.

### 2.1 랜덤 이벤트

탐험할 때마다 다른 상황을 만나도록 동굴 내부에 확률형 이벤트를 배치한다.

-   [x] 버려진 보급실
-   [x] 잠긴 보물방
-   [x] 무너진 통로와 우회 경로
-   [x] 고대 제단 및 선택형 보상
-   [x] 떠돌이 상인 또는 임시 거래 장소
-   [x] 위험을 감수하고 보상을 얻는 이벤트
-   [x] 이벤트가 특정 구역과 깊이에 따라 다르게 등장하도록 구성
-   [x] 같은 이벤트가 지나치게 반복되지 않도록 출현 빈도 조정

**설계 기준:** 이벤트는 단순한 장식이 아니라 자원 소비, 경로 선택, 보상
획득 중 하나 이상의 의미 있는 선택을 제공해야 한다.

### 2.2 지상 거점

탐험에서 얻은 코인·유물·희귀 자원을 사용해 지상 거점을 발전시킨다.

-   [x] 거점 화면 및 시설 배치
-   [x] 작업대: 제작 가능한 장비와 도구 확장
-   [x] 보관함: 자원 및 수집품 관리
-   [x] 연구실: 유물이나 희귀 자원을 연구해 영구 효과 해금
-   [x] 전시실: 발견한 유물을 전시하고 수집 진행도 확인
-   [x] 시설별 업그레이드 단계 및 비용 설정
-   [x] 거점 발전에 따라 새로운 기능과 탐험 선택지 해금
-   [x] 거점 진행 상황 저장 및 불러오기

**설계 기준:** 거점은 기존 코인 업그레이드 메뉴를 대체하기보다, 장기
목표와 새로운 기능을 제공하는 별도의 성장 요소로 설계한다.

### 2.3 희귀 자원 및 장비 제작

깊은 구역이나 특별한 장소에서만 얻을 수 있는 자원을 추가한다.

-   [x] 구역별 희귀 광물과 재료 설계
-   [x] 희귀 자원의 출현 조건과 획득 난이도 설정
-   [x] 희귀 자원을 사용하는 장비 제작법 추가
-   [x] 장비별 효과와 사용 상황 구분
-   [x] 장비 제작에 필요한 작업대 또는 거점 조건 설정
-   [x] 일반 업그레이드와 장비 제작의 역할이 겹치지 않도록 조정
-   [x] 희귀 자원의 보유량·사용처·획득 기록 표시

장비 예시: - 강화 곡괭이: 특정 광물이나 단단한 벽을 더 효율적으로 채굴 -
방한 장비: 특정 환경에서 생존 부담 감소 - 확장 랜턴: 빛의 범위 또는 지속
시간 개선 - 탐지 장비: 주변 자원이나 숨겨진 장소 발견에 도움

**설계 기준:** 장비가 필수 조건이 되어 특정 장비가 없으면 진행할 수 없는
상황은 피한다. 선택에 따라 탐험 방식이 달라지는 방향을 우선한다.

### 2.4 몬스터 도감

몬스터를 발견하거나 처치하면 정보를 도감에 등록한다.

-   [x] 기존 몬스터별 도감 항목 제작
-   [x] 몬스터 이름, 외형, 출현 구역 기록
-   [x] 공격 방식과 특징 설명
-   [x] 처치 횟수 및 최초 발견 기록
-   [x] 몬스터별 드롭 아이템 기록
-   [x] 모든 몬스터 발견·처치 보상 설계
-   [x] 보스 전용 도감 항목 추가

**설계 기준:** 도감 정보는 실제 게임에서 확인한 내용만 공개한다. 아직
발견하지 못한 몬스터는 실루엣이나 미확인 표시로 처리한다.

### 2.5 탐험 기록 및 통계

플레이어의 장기적인 진행 상황을 기록한다.

-   [x] 총 탐험 횟수
-   [x] 최고 도달 깊이
-   [x] 총 생존 시간
-   [x] 총 획득 코인
-   [x] 발견한 유물 수와 전체 수집률
-   [x] 발견한 몬스터 수
-   [x] 처치한 몬스터와 보스 수
-   [x] 가장 많이 사용한 아이템
-   [x] 탈출 성공 횟수 및 탐험 종료 횟수
-   [x] 기록 화면 및 통계 UI
-   [x] Steam 업적과 연결할 수 있도록 기록 데이터 구조 정리

**설계 기준:** 통계는 플레이어의 진행을 보여주는 데 사용한다. 불필요하게
많은 수치를 한 화면에 표시하지 않고 핵심 기록부터 제공한다.

## 9. 개발 원칙

1.  새로운 시스템을 추가하기 전에 기존 게임 루프와 충돌하지 않는지
    확인한다.
2.  콘텐츠의 양보다 플레이어가 실제로 선택하고 활용할 수 있는지를
    우선한다.
3.  랜덤 요소는 매번 다른 경험을 제공하되, 불공정한 결과를 만들지 않도록
    한다.
4.  Poki 버전은 짧은 시간에도 재미를 느낄 수 있도록 하고, Steam 버전은
    장기적인 성장과 수집의 깊이를 강화한다.
5.  플랫폼 전용 기능은 공통 게임 로직과 분리해 나중에 수정하기 쉽게
    만든다.
6.  기능을 추가할 때마다 PC·모바일 테스트와 저장 데이터 호환성을
    확인한다.
7.  출시 전에는 새로운 콘텐츠 추가보다 밸런스·안정성·완성도를 우선한다.

> **최종 방향:** Poki에서 핵심 게임성을 검증하고, 유저 반응을 바탕으로
> 탐험·수집·거점 성장 콘텐츠를 확장한 뒤 Steam에서 완성도 높은 장기
> 플레이 게임으로 출시한다.
